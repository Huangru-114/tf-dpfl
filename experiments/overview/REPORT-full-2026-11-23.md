## 1. 一页总览

### 1.1 研究问题

系统是**三层联邦学习**：云（cloud）— 边缘服务器（edge，下文简称「边缘」）— 客户端（client）。客户端用个性化联邦学习方法 **FedRep**（共享特征主干 + 每个客户端私有的分类头）。攻击是 **Bad-PFL**（ICLR 2025 的个性化后门攻击，触发器是逐样本的小幅对抗扰动）。研究两件事：

- 这种后门在分层结构里**怎样植入、怎样跨边缘传播、攻击者离开后怎样衰减**；
- **边缘**（假设可信、部署在机构内部、持有 500 张干净图片、有算力）能不能成为防御的主角。

| 阶段 | 核心问题 | 状态 |
|---|---|---|
| 一：攻击刻画 | Bad-PFL 在 FedRep 下何时植入、能持续多久 | 完成；在 Bad-PFL 官方代码（不分层）里做，原始数据不在本仓库（§3） |
| 二：分层机制（实验 3 改版） | 边缘**能看到什么、何时能干预、在哪一层干预** | **已结项**（2026-10-03 终版报告；123 个正式 run 回传） |
| 三：边缘原生防御 | 利用可信边缘的数据与算力防御 | **收尾中**（2026-10-09 定稿计划；112 个正式 run；三条防御线 + 三层个性化 + 中位数基线都已出结论；剩离线探针、攻击基线、自适应攻击者最小版） |
| 论文整合 | 把三个阶段写成一篇学位论文 | **进行中**（11-19 起；提纲 v2、论点—证据对照表、统一对比表、第 4–6 章 17 张论文图已有） |

**论文的一句话叙事**（INTEGRATION-PLAN，用户已确认）：在三层个性化联邦学习里，优化型后门是在**云聚合那一刻**跨边缘扩散的；边缘看不出谁在投毒，但它可以决定哪些东西跨过云端边界——**防御的杠杆在机构之间的边界上，而不在机构内部**。全书用「每个云周期的灌入 − 洗掉」作统一的分析框架。

### 1.2 最重要的结论（10 条）

| # | 结论 | 强度 |
|---|---|---|
| 1 | **攻击在本设定下接近饱和**：不设防时，攻击者所在边缘的良性端约 0.97–1.0，受害边缘最终也到 0.95 以上。很多效应因此被「天花板」遮住。 | ✅（多组一致） |
| 2 | **后门只经云聚合跨边缘传播**：每次云聚合把受害边缘的 ASR 推高 0.13–0.27；两次云聚合之间，受害边缘自己的训练在「洗」后门（每个周期洗掉 0.11–0.22），但**洗掉追不上灌入**，周期末值一个周期比一个周期高，最终饱和（「锯齿」）。 | ✅ |
| 3 | **没有「训练后期更安全」的时段**：攻击者所在边缘在任何训练阶段一开始投毒就饱和。攻击者离开后，后门在约 200 个边缘轮内褪到「不投毒也有的底线」附近；不分层的联邦学习一样褪。 | ✅ |
| 4 | **边缘视角没有检测优势**：用单个上传更新的范数、余弦、功能分数检测恶意客户端，边缘内归一化与全局归一化一样好、也一样差。唯一强的单更新信号来自**批归一化（BatchNorm）统计量**（AUROC 约 0.90），而这个通道攻击者可零代价伪造（代码证据，没做自适应攻击实验）。 | ✅ |
| 5 | **三层个性化**（模型最后 1 个残差块只在边缘内平均、不上云）：攻击者集中在一台边缘时，把受害边缘的 ASR 从约 1.0 压到约 0.3，精度几乎不变；但**攻击者所在边缘的良性端完全不受保护**，攻击者分散到每台边缘时**无效**。新、旧两种数据划分都复现。 | ✅（旧划分预注册判定；新划分 3 个种子的对照读数） |
| 6 | **防御线 A：上传前加固**（边缘每个云轮末用 500 张干净图做对抗反学习）：集中布点下受害端 ASR 平均降 0.41（0.48 / 0.52 / 0.23），精度降 ≤ 0.015 → `protects_victims`；碰不到攻击者所在边缘；分散布点精度代价 0.030 超门槛。 | ✅ |
| 7 | **防御线 B：CCS**（客户端对抗训练 + 服务端按上传的 BatchNorm 统计量聚类剔除；只在不分层设置下做）：只开聚类时精度代价约 0.01 且稳定，但 5 个种子里 2 个失守；对抗训练让训练随机崩溃；「用统计量检测恶意客户端」已有两篇先例。 | ✅ |
| 8 | **防御线 C：边缘干净集作参照的过滤**（方向 2）：只打分时攻击者与良性端分得开（AUROC 0.85 / 0.90），真正按分数丢弃上传后只把 ASR 从约 1.0 压到约 0.6；12 格里只有「三层个性化开 + 分散布点」过了全部门槛；「组内更同质」的划分冷启动死锁；分数很可能**滞后于**后门，形成反馈循环。 | ✅（判定）+ 🔍（机制） |
| 9 | **三层个性化的代价与边界**（补充实验，11-23）：隔离块数 0 / 1 / 2 / 4 时受害边缘 0.996 / 0.281 / 0.046 / 0.027、精度代价 0.002 / 0.010 / 0.022；隔离 1 块相对「几乎不上云」多保住 0.018–0.022 精度，一个种子差一点没到 0.02 → `inconclusive`。**隔离是按边缘的**：布点 [9,1,0,0] 下干净边缘降 0.61–0.68，而只有 1 个攻击者的边缘照样失守（0.93–1.00）。 | ✅ |
| 10 | **已知防御基线：逐坐标中位数**（边缘层 / 云层，补充实验）几乎无效：受害边缘只降 0.004–0.105、仍在 0.89–0.99；每周期灌入不变。三格按「方向一致 + 精度不掉」判 `blocks`，但效应量远小于三层个性化。 | ✅（正文必须带效应量） |

### 1.3 一句话现状

三条防御线、三层个性化和中位数基线都出了结论，**没有一种做法同时做到**：(a) 分散布点下有效、(b) 保护攻击者所在边缘的良性端、(c) 精度代价 ≤ 0.02、(d) 经得起知道防御的攻击者。最便宜也最稳的是**三层个性化**（结构性隔离），它的代价与威胁边界已补测。现在的工作是论文整合 + 收尾补充实验（快照结构核查已于同日补强重跑、全过）：三个离线探针 → 六种较弱的基线攻击（接线时间盒 2026-12-06）→ 知道最后一块不上云的自适应攻击者（最小版）。

## 2. 共同设定

### 2.1 系统

| 项 | 取值 | 备注 |
|---|---|---|
| 数据 / 模型 | CIFAR-10；ResNet-10（卷积与 BatchNorm 对齐 PyTorch 版） | 只有这一种组合 |
| 客户端 | 100 个；每端 500 张（375 训练 / 125 留出测试），等大小、无放回 | 阶段二后期起的新划分；早期组用旧划分（客户端不等大） |
| 拓扑 | 4 台边缘 × 每台 25 个客户端；每轮全局 10% 客户端参与（每台边缘每个边缘轮约 2–3 个） | 不分层对照 = 1 台边缘 × 100 端 |
| 轮次 | 一个**云轮** = R 个**边缘轮**；**有效轮** = 云轮 × R（= 边缘轮数）。主线 R = 5、60 个云轮 = 300 有效轮 | |
| 个性化 | FedRep：每轮先训分类头（1 epoch）再训主干（5 epoch）；BatchNorm 的缩放 / 平移参数共享、**滑动统计量私有** | 统计量私有是对齐口径（P2）的规定 |
| 学习率 | 0.992^有效轮 衰减 | 按有效轮而不是云轮，避免不同 R 之间日程不同 |
| 聚合 | 边缘内按样本数加权平均上传；边缘到云平均共享主干 | 私有分类头从不上传 |

### 2.2 攻击：Bad-PFL

- 触发样本 = x + δ + ξ。δ = ε·G(x)：攻击者训练的**生成器**输出的**定向**扰动（推向目标类，ε = 4/255）；ξ = σ·sign(∇)：一步**非定向**扰动（σ = 4/255）。合计 ‖δ + ξ‖∞ ≤ 8/255（逐样本、肉眼几乎不可见）。
  原文消融（FedRep）：去掉 δ 只剩 12.82%，去掉 ξ 79.32%，两者都在 97.95% → δ 是主体。
- 目标类 = 0（飞机）；10 个恶意客户端（全局 10%）；投毒率 0.2（每个样本以 0.2 的概率被投毒）。
- 评估统一用一个**固定攻击者**的生成器；ASR 只数非目标类样本。
- **攻击者不知道有防御**（非自适应）——全部防御读数都在这个前提下。

### 2.3 攻击者布点

| 名称 | 写法 | 含义 |
|---|---|---|
| 集中（collocated） | [10, 0, 0, 0] | 10 个攻击者全在边缘 E0（**E0 = 15 个良性端 + 10 个攻击者**，不是全恶意）；E1–E3 内部干净 = **受害边缘**，后门只能经云聚合传过去 |
| 分散（distributed） | [3, 3, 2, 2] | 每台边缘都有攻击者 |

### 2.4 数据划分

| 划分 | 构造 | 用在哪 |
|---|---|---|
| 旧 noniid | 逐类 Dirichlet，客户端不等大；**没有边缘干净集** | 阶段二早期组（G6 / G7 / G8）、阶段三 CCS 线 |
| **C1 机构式设计**（现主线） | 每台边缘有自己的类比例表：E0 均衡，E1–E3 各偏重一对类（各 0.25），四台边缘的飞机占比都是 0.10；边缘内客户端再按 Dirichlet(0.5) 分 | 阶段二后期、阶段三主线 |
| C2–C4 | 在 C1 上只改飞机那一列（如 C3 只有 E3 缺飞机） | 阶段二 3-B |
| 等大小随机 | 边缘不对应机构（对照） | 阶段二 |
| 层级 Dirichlet | 边缘层和客户端层都抽 Dirichlet | 阶段二 3-B 的泛化扫描 |
| **固定客户端画像**（λ = 0.4，下称「组内同质划分」） | 边缘层同 C1；第 c 个客户端 = 0.6 × 本边缘分布 + 0.4 × 一对固定的类 | 阶段三方向 2（为体现「组内更同质」，见 §5.3.1） |

**边缘干净集**：每台边缘 500 张，按本边缘的分布切出，与客户端数据不相交；只在新划分下才有。

### 2.5 指标

| 指标 | 定义 |
|---|---|
| 新鲜个性化模型（fresh-PM） | 当前边缘下发的共享主干 + 客户端自己的私有分类头与 BatchNorm 统计量。**精度与 ASR 都在它上面测**（同一个模型）。「陈旧个性化模型」= 客户端上次被选中时的模型，只作副列 |
| 良性端 ASR | 良性客户端的 fresh-PM 对触发样本判成目标类的比例 |
| V / B0 / P | V = 受害边缘 E1–E3 良性端 ASR 的均值；B0 = 攻击者所在边缘 E0 的良性端；P = 全部良性端池化 |
| 精度（MTA / pm_acc） | fresh-PM 在客户端自己的留出测试集上的精度，末 10 点均值。精度代价门槛统一是 **0.02** |
| 底线（floor）与超额（excess） | floor = 攻击者在场、生成器照训、**一张都不投毒**时同一触发器的 ASR（对抗扰动本身就能骗过一部分样本）；excess = ASR − floor |
| margin | 触发样本上「目标类对数概率 − 其余类最大对数概率」，> 0 即判成目标类。ASR 贴顶时它仍在动 |
| 灌入 / 洗掉 | 灌入 = 一次云聚合后受害边缘 ASR 升了多少；洗掉 = 一个云周期内边缘内训练把它降了多少 |
| AUROC | 某个分数区分「攻击者的上传」与「良性端的上传」的能力：0.5 = 随机，1 = 完全分开 |

### 2.6 方法学纪律（为什么这些数可信）

- **口径**：与官方 Bad-PFL / FedRep 代码逐条审计差异（2026-09-24 起，十几条），2026-09-27 全部处理完后定为口径 **P2**；只有 P2 的 run 进结论，更早的结果只作背景。
- **逐位可复现**：P2 下同配置同种子跨节点、跨作业、跨提交的每轮校验和**逐位相同**（前提：每个 run 恰好 4 个 CPU 核）。之后加的每一个记录仪表（评估网格、更新几何、在线功能分数、参照打分）都在 GPU 上验证过「开 / 关逐位相同 = 不改变训练」。
- **预注册**：判定规则先写进台账并提交 git，再交作业；判定脚本先于数据入库并有测试。默认 3 个种子（42–44）；3 个种子时「bootstrap 置信区间全 > 0」等价于「三个种子都 > 0」。加种子只按预注册规则。
- **标签照实记录**：事后发现规则有漏洞也不改标签；用户看过数据后的判断单独记为「决定」，不改写结论措辞。

## 4. 阶段二：分层机制（实验 3 改版，已结项）

> 终版报告：`experiments/attack/hfl-mechanism/REPORT.md`（2026-10-03）。图在 `experiments/attack/hfl-mechanism/figures/final/`。

### 4.1 子实验与判定一览

| 子实验 | 问题 | 规模 | 结论 | 强度 |
|---|---|---|---|---|
| 3.1 对抗下限 | ASR 平台期里有多少只是「触发扰动本身骗过了模型」 | 18 run | 不是：floor 只有 0.04–0.10（判据 0.3）；但 floor 不可忽略，且随本边缘的目标类占比变化 | ✅ |
| 3.3 收敛门控 | 训练后期是否更难植入 | 15 run + 8 run 前置 | `not_gated`：没有安全时段 | ✅ |
| 3-C 锯齿 | 干净边缘在一个云周期内能否自清洁 | 27 run | 能（4 / 5 格 `self_cleaning`），但洗掉追不上灌入 → 仍饱和 | ✅ |
| 3-C 衰减 | 攻击者走后后门是否持续 | 3 + 3 run | 大部分褪去、剩少数长尾客户端；不分层一样 → 不是分层结构造成的 | ✅（标签 `user_decides`，用户判「退回底线」） |
| 3-D 可观测性 | 边缘视角能否更好地检测恶意更新 | 同 3-C | 没有优势（`no_edge_gain` / `undetectable`） | ✅ |
| 3-E 三层个性化 | 边缘内共享段能否阻断跨边缘传播 | 9 + 3 run | 集中布点 `blocks`；分散布点无效 | ✅ |

| 3.2 私有头吸收 | 私有分类头能否吸收后门 | — | 没做（搁置）；反面信号：白盒 ASR ≈ 主列 | ⏸ |

### 4.2 实验地基（试点组，P1 口径，只作背景）

- **可复现**：两次 run 在不同节点上，前 5 轮校验和逐轮相同、全部指标到小数点后 4 位相同。

### 4.5 3-C 云周期内的锯齿

**量**（规则写于数据之前）：受害边缘良性端 ASR。灌入 = 云聚合后评估点 − 上一云轮末；洗掉速率 r_down = (云聚合后 − 本云轮末) / R（每有效轮）。只取前半程。判据：三个种子都 ≥ 0.005 → `self_cleaning`；都 ≤ 0.001 → `no_cleaning`。

| 格（划分 · R） | r_down 42 / 43 / 44 | 平均灌入 | 每周期洗掉 | 末周期：云聚合后 → 周期末（42 / 43 / 44） | 判定 |
|---|---|---|---|---|---|
| C1 · R5 | 0.0388 / 0.0381 / 0.0230 | 0.197 | 0.166 | 1.00 → 1.00（三个种子） | `self_cleaning` |
| C1 · R10 | 0.0217 / 0.0252 / 0.0201 | 0.268 | 0.223 | 1.00 → 0.98 / 0.85 / 0.97 | `self_cleaning` |
| C1 · R20 | 0.0068 / 0.0065 / 0.0074 | 0.180 | 0.138 | 0.99→0.84 / 0.97→0.78 / 1.00→0.89 | `self_cleaning` |
| 随机 · R10 | 0.0200 / 0.0191 / 0.0142 | 0.228 | 0.177 | 1.00 → 0.96 / 0.73 / 0.99 | `self_cleaning` |
| 随机 · R20 | 0.0064 / 0.0053 / **0.0049** | 0.130 | 0.111 | 0.98→0.82 / 1.00→0.93 / 0.98→0.61 | `user_decides`（差 0.0001） |

- **洗掉 < 灌入**（🔍）：前半程每周期净升 0.02–0.05 → 「云聚合后 ≈ 1.0、周期末 0.6–1.0」是常态，最终饱和。

- 攻击者所在边缘的「反向锯齿」（🔍）：每次云聚合被三个干净边缘稀释（前半程降 0.20–0.69），周期内以约 0.033–0.041 / 有效轮爬回。

### 4.7 3-D 边缘视角的可观测性

**规则**（写于数据之前）：每个上传更新算几个分数，比较「边缘视角」（在本边缘、本窗口内归一化）与「全局视角」（从全部边缘抽同样多个更新当参照，50 次平均）的 AUROC。判读格 = C1 · 分散布点；三个种子 ΔAUROC 都 > 0.05 → `edge_better`；|Δ| 都 < 0.05 → `no_edge_gain`；全局 AUROC < 0.7 → `undetectable`。

| R | 分数 | Δ（边缘 − 全局）42 / 43 / 44 | 全局 AUROC 42 / 43 / 44 | 判定 |
|---|---|---|---|---|
| 10 | 可训练权重的更新范数 `norm_w` | 0.021 / 0.031 / −0.001 | 0.847 / 0.708 / 0.744 | `no_edge_gain` |
| 10 | 与全局其余更新的余弦 | 0.001 / 0.001 / 0.003 | 0.514 / 0.525 / 0.520 | `undetectable` |
| 10 | 与本边缘其余更新的余弦 | −0.003 / 0.003 / 0.004 | 0.617 / 0.614 / 0.597 | `undetectable` |
| 10 | 在线功能分数 `s_ck` | 0.007 / −0.005 / 0.006 | 0.516 / 0.545 / 0.535 | `undetectable` |
| 20 | `norm_w` | 0.015 / 0.030 / 0.001 | 0.841 / 0.750 / 0.738 | `no_edge_gain` |
| 20 | `s_ck` | 0.020 / 0.028 / 0.013 | 0.519 / 0.606 / 0.541 | `undetectable` |

（R20 的两个余弦分数同样 `undetectable`；功能分数 c_k = 在边缘干净集上，对每个类做定向对抗攻击的失败率，后门会让目标类特别容易被攻到。）

- **误报 5% 时的检出率**：`norm_w` 边缘视角 0.34 / 0.36、全局 0.28 / 0.31（R10 / R20）；`s_ck` 0.09–0.12；BatchNorm 统计量部分 `norm_s` 约 0.68。
- **范数的可分性主要来自 BatchNorm 统计量**：raw AUROC `norm_w` 0.74、`norm_s` 0.90–0.91。而 FedRep 下统计量私有，上传值只用来算边缘 / 全局模型精度，不进任何受害者模型 → **自适应攻击者可零代价上传干净统计量**（代码证据，没有实验）。
- 集中布点下边缘视角反而更差（🔍）：E0 的 750 个上传里约 40% 是恶意的，参照池被污染。
- 两份盲算的独立实现，13 个判定标签全部相同。

### 4.9 3-B 目标类分布：判不出（天花板下的机械结果）

**设计**：C1 与 C3 只差「E3 有没有飞机」（0.10 vs 0.005）。预注册量 = 差中差 DiD = [E3 − (E1+E2)/2]_C3 − [同]_C1，用超额 ASR；区间全 < 0 → 迁移依赖目标类的自然特征；含 0 → 无差异。

| 种子 | DiD（原始 ASR） | DiD（floor） | **DiD（超额）= 原始 − floor** |
|---|---|---|---|
| 42 | +0.003 | −0.073 | +0.077 |
| 43 | +0.020 | −0.046 | +0.067 |
| 44 | +0.008 | −0.060 | +0.068 |

- 均值 +0.070，区间全 > 0 → **两条预注册分支都没落上**。
- 原因：原始 ASR 在 C1 / C3 都贴着天花板（0.85–0.99），DiD ≈ 0；C3 的 E3 没有飞机 → floor 只有 0.003–0.005 → 「减 floor」把 floor 的差原样搬进了结论。**这组数据既不支持也不否定 3-B 的假设。**
- 🔍 C2（攻击者边缘富含飞机、受害边缘都缺）受害边缘只有 0.53 / 0.60 / 0.62，比 C1 低约 0.35；但 C3 的 E3 并不低 → 「受害边缘缺目标类 → ASR 低」解释不了 C2，机制没有证据。

### 4.12 阶段二的综合

**后门在分层联邦学习里的生命周期**（测量）：

1. **植入**：攻击者所在边缘任何时候一开窗就饱和；平台期不是对抗扰动本身的效应。
2. **传播**：每次云聚合把攻击者边缘的主干平均进全局模型，受害边缘跳升 0.13–0.27；同一时刻攻击者边缘被稀释。
3. **周期内**：受害边缘每有效轮洗掉 0.005–0.04，攻击者边缘以约 0.035 / 有效轮爬回。
4. **净效果**：洗掉 < 灌入 → 受害边缘逐周期升高、最终饱和。
5. **攻击者走后**：同一个洗掉过程不再被抵消 → 约 200 有效轮褪到底线附近，留下 2–6% 的长尾客户端；不分层一样。

（推断）锯齿与衰减是同一机制的两面：干净训练一直在把主干拉回干净解，攻击者在场时被云聚合的灌入抵消。没有直接检验。

**对三个核心问题的回答**：

| 问题 | 回答 |
|---|---|
| 边缘能看到什么 | 单个上传上，边缘看到的不比「同样多个随机抽来的全局更新」多；唯一像样的信号是范数，主要来自可伪造的 BatchNorm 统计量；主干级的功能分数能看出「有没有后门」，分不出是哪台边缘 |
| 何时能干预 | 没有安全时段；攻击者在场时边缘自清洁每周期被抵消；攻击者走后系统会自己恢复（约 200 有效轮） → 防御要从第 1 轮一直开、作用在**云聚合之前** |
| 在哪一层干预 | 边缘内共享段（三层个性化）在攻击者集中时有效、代价小，但治不了攻击者所在边缘；边缘内检测没有依据；主线 = **边缘在上传前主动加固**（当时还没有证据 → 阶段三的第一个问题） |

### 5.1 防御线 A：上传前加固（已结案）

**设定**：主线（4 台边缘 × 25 端、C1 划分、FedRep、统计量私有、R5 × 60 云轮）。

**① 不设防对照（SNAP 组，6 run）**：集中 / 分散 × 种子 42–44。集中布点与阶段二同配置前 60 轮逐位相同。对照已饱和：受害端 0.995–0.997、精度 0.862–0.876；分散池化 0.961–0.998。同时存了第 6 / 15 / 60 云轮的快照供离线回放。

**② 离线筛选（P0，零训练）**：在快照上让 4 台边缘各用自己的 500 张干净图做一次加固，看下一次云聚合灌进受害边缘的后门少了多少（削减率，1 = 全削掉），共 36 种配置。

| 配置 | 削减率 @第 6 / 15 轮 | 池化精度降 @6 / 15 |
|---|---|---|
| TRADES ε = 8/255 | 1.81 / 0.91 | 0.535 / 0.434（模型坏掉） |
| PGD 对抗训练 ε = 4/255 | 0.83 / 0.88 | 0.111 / 0.089 |
| **SAU ε = 8/255 高预算**（离门槛最近） | **0.58 / 0.44** | **0.032 / 0.023** |
| SAU ε = 51/255（唯一过精度门槛） | −0.13 / 0.03 | −0.003 / 0.005 |
| 干净微调（无对抗，对照） | ≈ 0 | — |

- 判定 **`accuracy_bound`**（精度卡住）：削得动的都过不了精度门槛（SAU = 一种用小干净集做逐样本对抗反学习的后门清除方法）。
- 附带（🔍）：「阻尼」（每台边缘只吃一半云更新）第 6 轮削减率 0.61 且精度反而升，但只是一次性反事实；用私有统计量聚类分不开攻击者（命中 30%、误伤 54%）。

**③ 在线：每个云轮都在上传前加固**（SAU ε = 8/255 高预算）：

| 种子 | 受害端：对照 → 加固 | 降幅 | E0 良性端降幅 | 精度降 | 灌入量比值（加固 / 对照） |
|---|---|---|---|---|---|
| 42 | 0.995 → 0.519 | 0.476 | 0.048 | 0.009 | 0.79 |
| 43 | 0.997 → 0.475 | 0.522 | 0.002 | 0.013 | 1.01 |
| 44 | 0.996 → 0.769 | 0.228 | 0.000 | 0.015 | 0.96 |

- 判定：受害端 **`protects_victims`**；E0 良性端 **`no_effect`**。加固后 ASR 不饱和、逐点大幅振荡（种子 42 第 46–60 云轮在 0.24–0.65 之间）。
- **分散布点**（单种子）：池化 0.998 → 0.713，但精度降 0.030 → `marginal`，只记录。
- 开销：每次加固约 53 秒，训练墙钟 +116%；两个加固 run 装一张卡只多约 3% 墙钟。
- **起作用的方式**（🔍）：主要不是减少每次灌入，而是缩小每周期「灌入 − 洗掉」的净增量：前半程对照 0.026 / 0.032 / 0.033 → 加固 0.012 / 0.022 / 0.030；后半程加固臂停在不饱和的平衡。种子 44 净增量几乎没降，降幅也最小。
  两个口径不完全一致：按 ASR，灌入几乎不变（比值 0.79 / 1.01 / 0.96）；按 margin，灌入也降了约三分之一（2.00 / 2.00 / 1.75 → 1.37 / 1.44 / 1.07 logit）→ 论文措辞定为「**主要不是**靠砍灌入」（11-19 统一对比表之后更正）。
  → **离线筛选只量一次灌入，所以预测不了在线结果。**
- 没做：不投毒的底线实验（不能写「清除后门」）；5 个种子；每个边缘轮都加固（唯一可能碰到 E0 的做法，未实现）。

### 5.2 防御线 B：CCS（不分层设置，已收尾）

CCS（Cui et al., ICASSP 2026）= **客户端对抗训练** + **服务端对上传的 BatchNorm 统计量做聚类、剔除离群上传**。原文（不分层、FedPer）把 Bad-PFL 从 94.42% 压到 8.54%。⚠ CCS 官方代码本身跑不起来，本仓库照的是它的意图。

**设定与主线不同，数字只能和自己的对照比**：

| | 主线（防御线 A / C） | CCS 线 |
|---|---|---|
| 拓扑 | 4 台边缘 × 25 端 | **1 台边缘 × 100 端**（不分层） |
| BatchNorm 统计量 | 私有 | **共享**（随主干聚合；刻意偏离对齐口径） |
| 模型 | ResNet-10 | ResNet-10 + 私有投影网络（照 CCS 官方结构） |
| 划分 | C1 机构式设计 | CCS 原文的逐类 Dirichlet 0.5（客户端不等大） |
| 不设防对照的 ASR | ≥ 0.96 | 0.796（统计量共享）/ 0.926（统计量私有） |

**① 排查过程**（10-29 … 10-31，单种子，一次只改一个开关）：FedRep + 统计量私有 + CCS → 主任务从第 10 轮停在 0.34、第 54 轮数值溢出；改 FedPer（每步把全部参数一起训）→ 主任务不崩，但后门传不到良性端（0.39–0.41，复现闸判 `invalid_no_attack`，加大训练量也一样）；**统计量改为共享 → 不再崩**（30 轮主任务 0.70）。结论：主因是客户端私有统计量与每轮变化的共享主干失配。
- 统计量共享 + CCS（种子 42）：ASR 降 0.684、精度降 0.112 → `partial_repro`。
- 「统计量共享本身削弱后门」：三个种子都同向（低 0.130 / 0.109 / 0.017）、均值 0.085 < 0.10 → `not_established`。

**② 组件拆分**（只开聚类 5 个种子，其余 3 个种子）：

| | 种子 42 / 43 / 44 |
|---|---|
| 不设防：ASR / 精度 | 0.796 / 0.823 / 0.810；0.894 / 0.895 / 0.892 |

只开聚类的种子 45 / 46：ASR 0.830 → 0.076、0.951 → **0.606**；精度降 0.016 / 0.012。

- 预注册判定：**`cluster_alone_sufficient`**——5 个种子 ASR 降幅 0.614 / 0.139 / 0.762 / 0.753 / 0.345，均值 0.523（95% 区间 0.18–0.86），只比门槛 0.5 高 0.023；精度降幅均值 0.011（0.008–0.015）。**5 个种子里 2 个（43、46）各自不满足**。结论措辞：「精度代价小且稳、防御效果不可靠」。

**④ 先例**：「用 BatchNorm 统计量检测恶意客户端」已有 **BNGuard**（MobiHoc 2025）与 **CCS** 两篇，都不分层 → **统计量聚类本身不是本项目的贡献**。

### 5.3 防御线 C：边缘干净集作参照的过滤（「方向 2」，2026-11-19 收尾，不再交作业）

**思路**：每台边缘用自己的 500 张干净图当「信任锚」，给每个客户端上传打可疑分：把上传的权重装进一个草稿模型，在干净图上算各 BatchNorm 层的输入统计量，与这个上传自带的统计量比较（分数越大越可疑）；分数超过阈值就丢掉这个上传。用的是绝对阈值、不靠「少数服从多数」（每台边缘每轮只有 2–3 个上传，多数原则成不了簇）。
⚠ 主线（统计量私有）下上传里**也带**统计量（取值是主干训练段末尾的），只是不下发给客户端 → 方向 2 能留在正式口径里做（旧交接说「不上传」是错的）。

#### 5.3.1 先补的一件事：「组内更同质」在现主线划分里体现得很弱

用户指出「边缘内应当比边缘间更同质」是项目的核心假设。用「两个客户端类分布的总变差」（0 = 完全相同，1 = 完全不重叠）量：

| 划分 | 同边缘两端 | 跨边缘两端 | 比值 |
|---|---|---|---|
| 现主线 C1（边缘内 Dirichlet 0.5） | 0.549 | 0.696 | **0.79** |
| 层级 Dirichlet α = 0.3 / 0.1 | 0.469 / 0.367 | 0.794 / 0.899 | 0.59 / 0.41 |
| 等大小随机（边缘不对应机构） | 0.610 | 0.608 | 1.00 |
| **新：固定客户端画像 λ = 0.2 / 0.4 / 0.6** | 0.155 / 0.296 / 0.436 | 0.453 / 0.547 / 0.648 | 0.34 / **0.54** / 0.67 |

- 原因：Dirichlet(0.5) 下每台边缘内部本身就是一个完整的高异质联邦学习问题；客户端偏离本边缘分布（0.41）比边缘之间的差（0.375）还大。
- 方向 2 因此取两个划分水平：现主线（main）与固定画像 λ = 0.4（下称 homo）。

#### 5.3.2 第一段：只打分、全部接纳（ERP / ERPB 组，12 run，种子 42 / 开发种子 41）

预注册规则：每个划分在四格（三层个性化 关 / 开 × 集中 / 分散）上选「四格最小 AUROC 最大」的分数；阈值 = 不投毒开发 run 里该分数的 90% 分位点；四格最小 AUROC ≥ 0.75 → `feasible`。

| 划分 | 选中的分数 | 四格最小 AUROC | 四格 AUROC（关·集中 / 关·分散 / 开·集中 / 开·分散） | 判定 |
|---|---|---|---|---|
| main | 类混合残差（用干净集的逐类统计量拟合上传统计量，取残差） | **0.847** | 0.999 / 0.847 / 0.998 / 0.904 | `feasible` |
| homo | 逐客户端参照的 KL 散度（全部层） | **0.895** | 0.973 / 0.922 / 0.964 / 0.895 | `feasible` |

- 「记录不改训练」的闸通过：与不设防对照前 60 轮逐位一致。
- 回放（🔍，单种子）：main 集中布点攻击者几乎全被挡，**分散布点漏网 43% / 23%**；良性误剔 main 5–14%、homo 17–28%（名义 10%）。

#### 5.3.3 第二段：分数 > 阈值就丢弃上传（ERF 24 run + 对照 ERC 12 run，种子 42–44）

预注册规则：每格三个种子 ASR 降幅（良性端池化）均值 ≥ 0.15、最差种子 ≥ 0.10、精度降 ≤ 0.02 → `protects`；ASR 达标精度不达标 → `accuracy_bound`；否则 `no_effect`。本轮上传全被剔 → 本台边缘模型不变。

**现主线（main）**：

| 格子 | 标签 | ASR 降幅 均值 / 最差种子 | 精度降 | ASR：对照 → 过滤 | 在线：攻击者放行率 / 良性误剔率 |
|---|---|---|---|---|---|
| 三层个性化关 · 集中 | `accuracy_bound` | 0.420 / 0.337 | 0.0208 | 0.997 → 0.577 | 0.63 / 0.06 |
| 三层个性化关 · 分散 | `accuracy_bound` | 0.379 / 0.298 | 0.0236 | 0.986 → 0.607 | 0.46 / 0.11 |
| 三层个性化开 · 集中 | `no_effect` | 0.112 / −0.052 | 0.0135 | 0.399 → 0.286 | 0.64 / 0.05 |
| 三层个性化开 · 分散 | **`protects`** | 0.334 / 0.213 | 0.0123 | 0.956 → 0.622 | 0.45 / 0.07 |

集中布点下按边缘拆开（三层个性化关，种子 42 / 43 / 44）：受害边缘 0.995 / 0.997 / 0.996 → 0.440 / 0.553 / 0.615；**E0 良性端 0.998 / 1.000 / 1.000 → 0.709 / 0.747 / 0.887**——这是三条防御线里唯一动到 E0 良性端的，但仍高。

- 与三层个性化组合：集中布点 **`additive`**（过滤 + 三层个性化 0.286 < 只开三层个性化 0.399 − 0.10）；分散布点 `redundant`（0.622 ≈ 只过滤 0.607；只开三层个性化 0.956）。
- 关掉三层个性化的两格精度降 0.021 / 0.024，只比门槛高一点点。

**组内同质划分（homo）**：四格标签是 `accuracy_bound` / `no_effect`，但**全是冷启动死锁的产物，不作证据**：12 个过滤 run 的 1200 个边缘轮**全部** 100% 被扔。第 1 轮分数中位 0.0087 > 阈值 0.0041 → 全被剔则模型不变 → 模型停在初始值 → 下一轮分数照样高 → 300 轮一次都没更新（ASR 0.11–0.15 = 底线；精度 0.39 = 只有私有分类头在学）。

**死锁的原因**（用户问「是不是干净集选偏了」——**不是**）。开发 run 里两个分数在各训练阶段的中位数：

| 分数 | 划分 | 第 1 轮 | 2–5 | 6–30 | 31–100 | 101–300 | 第 1 轮 ÷ 后期 |
|---|---|---|---|---|---|---|---|
| KL（全部层） | main | 0.0094 | 0.0053 | 0.0039 | 0.0035 | 0.0038 | 2.48 |
| KL（全部层） | homo | 0.0087 | 0.0053 | 0.0039 | 0.0033 | 0.0035 | 2.45 |
| 类混合残差 | main | 0.1238 | 0.0944 | 0.0927 | 0.0993 | 0.1096 | 1.13 |
| 类混合残差 | homo | 0.1201 | 0.0964 | 0.0924 | 0.1002 | 0.1094 | 1.10 |

→ 同一分数在两个划分下走势几乎相同；第一段恰好给 homo 选了「训练初期是后期 2.5 倍」的 KL。死锁 = 分数选择 + 全程固定阈值 + 全被剔不更新三者叠加；main 若选 KL 也会死锁。规则漏洞（没有「模型从未训练」的闸）与执行疏漏（第一段只算了全程误剔、没查第 1 轮）照实记录。

#### 5.3.4 为什么过滤只能削弱：分数可能滞后于后门（🔍，相关性证据）

| 现主线 · 集中 · 种子 42，只看 E0 | 攻击者分数中位 | E0 良性端分数中位 | 「上一云轮 E0 良性 ASR」与「本轮攻击者分数」的相关 |
|---|---|---|---|
| 三层个性化关 · 不过滤 | 0.205 | 0.101 | 0.07 |
| 三层个性化关 · 过滤 | **0.095** | 0.096 | **0.57** |
| 三层个性化开 · 不过滤 | 0.218 | 0.107 | 0.20 |
| 三层个性化开 · 过滤 | **0.106** | 0.098 | **0.71** |

- 一过滤，攻击者的分数就降到和良性端一样，并且跟着「E0 模型被污染的程度」走；同格内放行率与 ASR 负相关（放行 0.86 / 0.36 / 0.67，ASR 0.49 / 0.59 / 0.66）。
- **解释（未直接验证）**：触发器是有界小扰动；模型没学会后门时，触发图片在模型眼里和普通图片差不多，统计量几乎不偏；学会之后同一触发器引起强烈内部响应 → 统计量偏移 → 分数高。于是：过滤压住后门 → 攻击者看起来正常 → 放行 → 后门回升 → 被拦 → 平衡在 ASR 约 0.3–0.6。推论：「只打分」测到的区分能力（AUROC 0.85）**高估**在线效果——与防御线 A「离线预测不了在线」是同一类教训。
- 可选验证（用户说做才做）：在 SNAP 快照（第 6 / 15 / 60 轮，后门由弱到强）上直接量「同一批干净图加触发器前后统计量偏多少」，约 1 个短 GPU 作业。

### 5.4 三层个性化（论文里叫「边缘级共享块」）：效果、代价与威胁边界

`federation.edge_shared_blocks: B`：ResNet-10 最后 B 个残差块只在边缘内平均、不上云（B = 1 时约 75% 的参数留在边缘，上云只剩约 25%）。

**① 效果**（B = 1；**不设防**对照、三个种子均值；新划分；数据 = SNAP / ERP / ERC 组）：

| 划分 | 布点 | 三层个性化 | 良性端 ASR | 受害边缘 | E0 良性端 | 个性化精度 |
|---|---|---|---|---|---|---|
| 现主线 | 集中 | 关 → 开 | 0.997 → **0.399** | 0.996 → **0.281** | 0.999 → 0.988 | 0.868 → 0.867 |
| 现主线 | 分散 | 关 → 开 | 0.986 → 0.956 | — | — | 0.869 → 0.867 |
| 组内同质 | 集中 | 关 → 开 | 0.926 → **0.418** | 0.911 → **0.302** | 0.999 → 1.000 | 0.844 → 0.845 |

- 受害边缘的种子间差异不小：现主线开三层个性化后 0.331 / 0.197 / 0.315，组内同质 0.498 / 0.053 / 0.356。
- 旧划分（阶段二 G6）：k = 1 / 2 时受害边缘降 0.524 / 0.730（fresh 精度代价 ≤ 0.02；陈旧口径 k = 2 约 0.028）。

- 机制（统一对比表，描述性）：集中布点前半程，每次云聚合的灌入按 ASR 口径从 0.220 / 0.222 / 0.148 降到 0.035 / 0.072 / 0.071（砍到 1/3–1/6），按 margin 口径从 2.00 / 2.00 / 1.75 降到 0.94 / 1.20 / 1.01 logit（约一半）→ 它是**砍灌入**的防御。

**② 代价对照：块数扫描**（TBS 组，集中布点 × B ∈ {1 存快照, 2, 4} × 3 种子；B = 0 用 SNAP；补充实验 D1，11-23）

问题：效果会不会只是「共享得少」的平凡后果？预注册量 D = 精度(B=1) − 精度(B=4)（B = 4 = 只剩输入层上云）；三个种子都 D ≥ 0.02 → `b1_meaningful`；都 |D| < 0.01 → `isolation_free`。

| 块数 B | 上云参数比例 | 受害边缘 | E0 良性端 | 精度 | 陈旧模型精度 |
|---|---|---|---|---|---|
| 0（不设防） | 100% | 0.996 | 0.999 | 0.868 | 0.902 |

- D = 0.0202 / 0.0223 / **0.0182** → **`inconclusive`**（种子 44 差一点没到 0.02）；用户定不补种子、报数字不报方向。论文写法：「B = 1 相对几乎完全隔离多保住的精度在三个种子上是 0.018–0.022」，不说「有意义」，也不说「切断是免费的」。
- 受害边缘随 B 单调下降（三个种子都是）；**B = 2 已把受害边缘压到 0.046**，比 B = 1 多压 0.235、精度多降约 0.008；E0 良性端在任何块数下都约 1.0。

- 局限：按类精度没有记录 → 「个性化评估只测本地分布，可能低估共享的价值」写进有效性威胁。

**③ 威胁边界：布点 [9,1,0,0]**（TBH 组，B ∈ {0, 1} × 3 种子；补充实验 D2，11-23）

问题：隔离是「按边缘」的吗？E0 有 9 个攻击者、E1 有 1 个、E2 / E3 干净。

| 种子 | 干净边缘 E2 / E3（B=0） | E2 / E3（B=1） | 干净边缘降幅 | E1 良性端（B=1） | E1 − 干净边缘（B=1） |
|---|---|---|---|---|---|
| 42 | 0.944 / 0.996 | 0.264 / 0.310 | 0.683 | 0.931 | 0.644 |
| 43 | 0.886 / 0.959 | 0.248 / 0.300 | 0.649 | 0.999 | 0.725 |
| 44 | 0.975 / 0.992 | 0.246 / 0.504 | 0.608 | 0.941 | 0.566 |

- 两个判定都过：`clean_protected`（三个种子降幅都 ≥ 0.30）+ `e1_breached`（差都 ≥ 0.20）。事先写下的预测是 `clean_protected`、E1 不确定 → 「信任域」解释从「和数据一致」升为「**事先预测、被检验**」。
- 含义：隔离是**按边缘**的——最后一块只被良性端训练的边缘受保护；边缘里只要有**1 个**攻击者（25 个客户端里参与频率约 10%），该边缘的良性端就和攻击者所在边缘一样失守。精度 B=0 0.867、B=1 0.868。

**④ 结构核查**（D0）：CPU 小联邦真跑一个云轮（B = 1 / 2 / 4）全过；真实快照上的核查第一次四条全过（全局上云段 = 四台边缘上云段的等权平均，残差约 4e-8；边缘段从未上云；四台边缘的边缘段两两不同；客户端私有部分两两不同），
但核查本身发现两个盲点（四台边缘上云段完全相同时也会通过；拟合只覆盖前 40 万个坐标）→ 已补强（拟合矩阵满秩、四台边缘上云段两两不同、拟合用全部 1 227 712 个坐标），同日重跑三个种子 × 三个快照轮**仍全过**（F-133）→ 这一节的结构前提成立。

**小结**：
- **有效的地方**：攻击者集中在少数边缘时，几乎不花精度就把其他边缘的后门压掉六七成（B = 2 时九成以上）；组内同质与否不影响；靠的是砍灌入。
- **盲区**：① 攻击者所在边缘（以及任何有攻击者的边缘）的良性端完全不受保护；② 攻击者分散到每台边缘时没有作用（0.96–0.99）。
- **还没回答**：知道边缘段的攻击者（只往上云的层写后门）下还剩多少 → 论文做最小版（§7.2）；后门有多少「存」在最后一块里、受害边缘低 ASR 是「后门没传过来」还是「触发器迁移不过去」→ 离线探针（§7.2）。
- 定位：结构本身有先例（ESPerHFL、HPFL 等，只为精度），卖点是「后门隔离作用」及其边界。

### 5.7 文献定位（2026-11-17 核查；大部分据摘要）

- 没找到同时占「三层结构 + 个性化 + 优化型触发器 + 边缘主导防御」四样的工作。
- 方向 2 最近的先例 **FoggyTrust**（分层、雾节点各持 100 张根数据算信任分）：针对模型投毒、不个性化、用更新余弦，**前提是组内同质**（作者自承组内差异大时失效）。
- **SURA**（单服务器、干净图 + 统一 BatchNorm 参照）：在代理集泄露 + 方向幅度联合调整下被绕过（ASR 94.91%）→ 威胁模型要写明边缘干净集保密。
- 统计量检测的先例：BNGuard、CCS（都不分层）；分层场景的后门防御（SHIELD 等）都不用统计量。
- 「在线过滤 → 反馈循环 → 离线高估在线」没找到对应工作（只读了摘要）。

### 6.1 可以写进报告的结论

| 分层下 Bad-PFL 的后门经云聚合传播，边缘内自清洁追不上灌入 | ✅ 27 run、4 / 5 格 | 只测了 4 台边缘、R ∈ {5, 10, 20}、单一攻击 |

### 6.2 不能说的（常见误读）

- ❌「上传前加固清除了后门」——没有不投毒的底线实验，只能说「压低」。
- ❌「组内同质划分下参照过滤非常有效（ASR 降到 0.12）」——那是冷启动死锁、模型从未训练。
- ❌「统计量聚类是本项目的贡献」——BNGuard、CCS 已有。
- ❌「主线下 BatchNorm 统计量不上传」——上传了，只是不下发给客户端。
- ❌「集中布点下 E0 全是攻击者」——E0 = 15 个良性端 + 10 个攻击者。
- ❌「3-B 的差中差显著，说明迁移依赖目标类特征」——那是 floor 差的机械结果。
- ❌ 把 CCS 线的数字和主线直接比较——拓扑、统计量、划分、模型四个因素都不同。
- ❌「Multi-Krum 在本仓库挡不住」——旧方案里那 6 个防御格子根本没开防御（作业脚本把它覆盖成了 none）；补充实验只测了逐坐标中位数，Multi-Krum 没有有效数据（文献里不分层设定下它挡不住）。
- ❌「中位数判 `blocks`，所以有效」——`blocks` 只要求方向一致 + 精度不掉，受害边缘仍在 0.89–0.99。
- ❌「三层个性化的代价对照证明了它不只是少共享」——判的是 `inconclusive`，只能报 0.018–0.022 这个数。
- ❌「三层个性化保护所有良性机构」——边缘里只要有 1 个攻击者就失守。

### 6.3 贯穿三个阶段的教训

1. **攻击饱和遮住效应**：不设防时 ASR 0.96–1.0，3-B 因此判不出，「部分有效」也难看清。计划里的「不饱和工作点」（降投毒率 / 攻击者比例）一直没跑。
2. **离线 / 只记录会高估在线**：离线一次加固预测不了在线加固（§5.1）；只打分的 AUROC 高估在线过滤（§5.3.4）。防御一旦介入，攻击者的可观测量会跟着变。
3. **BatchNorm 统计量是一把双刃剑**：它是唯一强的单更新信号（阶段二 0.90；阶段三参照打分 0.85–0.90），CCS 与方向 2 都靠它；但它可零代价伪造，而且可能只在后门已被学会后才偏移。
4. **结构性隔离比检测稳**：三层个性化不需要识别谁是攻击者，在它的适用范围（攻击者集中）内比任何检测类方法、也比逐坐标中位数便宜而稳定；它的边界恰好是检测类方法也没解决的两种情形。论文据此把这两种情形写成「问题退化成边缘内部的不分层问题」（不分层下已知防御在 Bad-PFL 原文里基本失效）。
5. **「边缘 = 机构、组内更同质」在现主线划分里体现得很弱**（0.79）；这条假设影响所有「利用边缘」的防御设计。

### 7.2 已排好的下一步（预注册规则 N-015 已生效；一个会话一件事）

1. ✅ **快照结构核查的补强版重跑**（11-23 已回传）：新增「拟合矩阵满秩」「四台边缘上云段两两不同」都过，三层个性化的结构核查写成最终结论（F-133）。
2. **三个离线探针**（约 1–2 GPU 小时 + 一个离线脚本）：
   - 重训最后一块：在攻击者所在边缘的快照模型上只重训最后一块，看 ASR 降多少（f = 降幅 / (原 ASR − 底线)）；三个种子都 f ≥ 0.5 →「后门主要在最后一块」；都 < 0.25 →「主要在前面的层，6.1 的机制解释要改写」。闸：干净精度降 ≤ 0.05。
   - 受害模型上白盒求扰动：受害边缘低 ASR 是「后门没传过来」（白盒 − 主列都 < 0.10）还是「触发器迁移不过去」（都 ≥ 0.30 且白盒 ≥ 0.5）。
   - 统计量偏移随后门强弱：108 个边缘模型上，触发器引起的统计量偏移与后门强度的秩相关；合并 ≥ 0.5、每个种子内 > 0、置换 p < 0.01 → 反馈循环的证据从「弱」升为「中」；≤ 0.2 → 不支持。
3. **六种较弱的基线攻击**（BadNets、Blended、DBA、Neurotoxin、CerP、IBA；**接线时间盒 2026-12-06**，到期没接通的写进局限）：
   - 现状：正式口径下只有 Bad-PFL 接了按 epoch 重洗的取数路径，其余都会被启动校验拒绝 → 要先写接线代码（三种静态触发器共用一个；IBA 主线没有实现，要照官方代码新写；Neurotoxin 掩码方向未证实；CerP 触发器训练还读旧管线）。
   - 探路：每种 × 不设防 × 集中 × 种子 42；受害边缘 ≥ 0.30 → `propagates` → 进正式实验 {不设防, B=1, 上传前加固} × 集中 × 3 种子；否则补种子作「为什么必须研究 Bad-PFL」的证据。分散布点不做。
   - 顺序：静态三种 → IBA → 自适应攻击者 → Neurotoxin / CerP。
4. **自适应攻击者最小版**：知道最后一块不上云的 Bad-PFL 攻击者（投毒训练时把最后一块的梯度置零，只往上云的层植入）× 集中 × B=1 × 3 种子；三个种子都比普通 Bad-PFL 高 ≥ 0.30 → `b1_breached`（6.1 写明「对知道边界的攻击者无效」）；都 < 0.10 → `b1_holds`。闸：E0 良性端 ≥ 0.5。
5. **写作**（与上面并行）：第 4 章 → 第 5 章 → 6.1–6.3 → 第 3 章 → 第 2 章 → 第 7、8、1 章 → 英文与瑞典语摘要。

## 9. 局限

- **数据与模型**：只有 CIFAR-10 + ResNet-10；只有 FedRep 一种个性化方法；目前只有 Bad-PFL 一种攻击（六种基线攻击在接线中，时间盒 2026-12-06）。
- **威胁模型**：全部防御读数都在非自适应攻击者下；BatchNorm 统计量通道可伪造这一条只有代码证据。
- **种子**：主结论 3 个种子（原计划主结论 5 个）；分散布点加固、CCS 排查、3-A 都是单种子。
- **饱和**：攻击接近饱和，多个子实验撞天花板。
- **口径**：fresh-PM 作主列会低估干净精度（最多 0.094）；三层个性化 k = 2 的精度代价在陈旧口径下超门槛。
- **拓扑**：主要是 4 台边缘 × 25 端；边缘数是否改变防御效果没测。
- **CCS 线**：只在不分层、统计量共享下做；官方代码本身跑不起来，不可能逐位对拍。
- **代码里已知未修**：FLAME 未按文献实现且用全局随机数；Neurotoxin 掩码方向；防御的距离计算里混进私有分类头（只有代码路径证据）。
- **判定脚本的时序**：三层个性化（G6）与 3-C / 3-D（G1）的判定**规则**写于数据之前，**脚本**写于部分数据之后（git 可查）。

## 附录 A：术语表

| 术语 | 含义 |
|---|---|
| 分层联邦学习 | 云 – 边缘 – 客户端三层；边缘内先聚合，边缘再到云聚合 |
| 边缘（edge） | 中间层服务器；本项目假设可信、部署在机构内部、持 500 张干净图 |
| 云轮 / 边缘轮 / 有效轮 | 一个云轮 = R 个边缘轮；有效轮 = 边缘轮的累计数，用来跨不同 R 比较 |
| FedRep | 个性化联邦学习方法：主干共享、分类头私有；每轮先训分类头再训主干 |
| FedPer | 同样主干共享、私有层私有，但每一步都把全部参数一起训 |
| Bad-PFL | ICLR 2025 的个性化后门攻击：触发器 = 生成器的定向扰动 δ + 一步非定向扰动 ξ |
| CerP / IBA | 计划中的第二攻击（可训练的块状触发器 / 生成器噪声触发器） |
| BatchNorm 统计量 | 批归一化层记录的激活均值与方差；「私有」= 各客户端自己的、不下发；「共享」= 随主干聚合 |
| 新鲜个性化模型（fresh-PM） | 当前共享主干 + 客户端自己的私有部分；精度与 ASR 都在它上面测 |
| ASR / 良性端 ASR | 攻击成功率；本文默认指良性客户端的 fresh-PM、只数非目标类样本、末 10 个评估点均值 |
| V / B0 / P | 受害边缘良性端 / 攻击者所在边缘的良性端 / 全部良性端池化的 ASR |
| floor / excess | 不投毒时同一触发器的 ASR / ASR 减去 floor |
| margin | 目标类对数概率减其余最大对数概率；ASR 饱和时的连续量 |
| 灌入 / 洗掉 | 云聚合带来的受害边缘 ASR 跳升 / 云周期内边缘训练带来的下降 |
| 集中 / 分散布点 | 攻击者全在 E0 / 每台边缘都有攻击者 |
| 三层个性化（边缘段） | 模型最后 k 个残差块只在边缘内平均、不上云；论文里叫「边缘级共享块」（edge-shared blocks） |
| 块数 B | 三层个性化隔离的残差块数；B = 1 上云约 25% 参数，B = 4 只剩输入层上云 |
| 逐坐标中位数 | 对每个参数坐标取各上传（或各边缘模型）的中位数，经典的鲁棒聚合基线 |
| 灌入—洗掉分解 | 论文的统一分析框架：每个云周期受害边缘的变化 = 灌入 − 洗掉；净增量 > 0 就走向饱和 |
| 上传前加固 | 每个云轮末，边缘在上传前用自己的干净图做对抗训练（本项目选的是 SAU） |
| SAU | 一种用小干净集做逐样本对抗反学习的后门清除方法 |
| CCS | ICASSP 2026 的防御：客户端对抗训练 + 服务端按上传的统计量聚类剔除 |
| 缓存池 | 聚类时把其余客户端最近一次上传的统计量也放进来，扩大参照池 |
| 参照过滤（方向 2） | 边缘用干净集当参照，给每个上传的统计量打分，超阈值丢弃 |
| AUROC | 分数区分攻击者与良性端的能力；0.5 = 随机，1 = 完全分开 |
| 口径 P2 | 与官方实现逐条对齐后的正式实验口径；只有 P2 进结论 |
| 预注册 | 判定规则在看数据之前写好并提交 |
