# exp006 — badpfl × fedrep × resnet10，「对齐论文 fraction/poison」的尝试

- **配置（仓库内）**：`full_p4_resnet.yaml` = 100 client / 2 edge / 10 mal(spread) / cifar10 /
  hier_fedrep / defense=none / resnet10(BN) / **client_fraction=0.1 / poison_ratio=0.2** / 80 round。
- **恶意端**：编号为 11 整倍数的 10 个终端 = `[0,11,22,33,44,55,66,77,88,99]`。
- **metrics**：`exp006.metrics.json`
- **动机**：exp004 结论是「过度参与/过度投毒把主任务打崩」。本 run 把 fraction、poison
  降到论文值（0.1 / 0.2），看 acc 是否回到 ~0.72。**结果 pm_acc 仍崩到 0.4156。**

|---|---|---|---|---|---|---|---|

## ✅ 真正的根因（据 r47 / r79 原始训练日志，2026-08-23 用户提供）

> **先纠正一处此前的误判**：我曾据「10 恶意端 × 全部 80 轮参与」在 frac=0.1 下的
> 概率反推「exp006 没跑在 0.1 上」。**这是错的**，被原始日志证伪 —— 恶意端每轮全参与
> 不是因为 fraction≈1.0，而是因为**集群的 `select_clients` 强制把恶意端固定选进每一轮**。

原始日志揭示的选择行为（每个 edge_round、每个 global round 都一样）：

| edge | 每 edge_round 选中集合 | 恶意端 | 良性端 |
|---|---|---|---|
| **Edge 0**（"Selected **7**/50"）| 恒为 `{0,11,33,55,66,88,99}` | **7 个（全部）** | **0 个** |
| Edge 1（"Selected 5/50"）| 恒含 `{22,44,77}` + 2 个轮换良性 | 3 个（全部） | 2 个轮换 |

**选择语义（据日志推断）**：`n_select = max(int(frac·n_edge), n_malicious_in_edge)`，
恶意端**全部强制选入**，剩余名额才给随机良性。
- Edge 0：`max(int(0.1·50), 7) = max(5,7) = 7` → 7 恶意端**吃满**名额 → **良性端一个都进不来**。
- Edge 1：`max(5,3) = 5` → 3 恶意 + 2 随机良性。

### 由此推出 pm_acc 崩溃的机制（FedRep 特有）

**Edge 0 的 ~43 个良性端从头到尾从未被选中训练** → 在 FedRep 下，私有 head 只在客户端
被选中时本地训练 → **这些良性端的 head 永远停在初始化** → 个性化模型输出近乎常数类。
这正解释 log_tail 混淆矩阵**所有类塌向类 3**（未训练 head 的退化预测），以及
pm_acc 卡在 0.41（干净基线 0.72）。同时 Edge 0 的共享 backbone **100% 由攻击者更新**
（日志里 edge0 恶意端 loss ≈ 0.001–0.01，过拟合投毒），benign 无任何干净梯度进入。

### 为什么「降 client_fraction 到论文值」不但没用、反而伤害

降 frac → `int(frac·n_edge)` 名额更小 → 越容易被强制选入的恶意端吃满 → **越多良性端
被饿死**。这是**选择逻辑 × 拓扑**的接线问题，不是「投毒太狠」本身，也不是论文的设定
（论文里攻击者是被采样 cohort 的一部分，不是每轮强制 pin 进一个缩小的名额）。
