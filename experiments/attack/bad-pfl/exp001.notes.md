## 判据结果（按 current-focus.md 事先约定）

> **⚠️ 本 run 是 5-round smoke，只能验「接线」，不能判「算法/迁移性」。**
> smoke-base.yaml 自述用途即「验证接线而不是算法」。有效训练轮 =
> `n_rounds × edge_rounds = 5 × 2 = 10`，远不足以让后门在共享 backbone 中累积或迁移。
> 后门植入/迁移的有效判据需要 `round × edge_round ≈ 300~500` 的全长 run（见文末）。

## 结论：接线 PASS + 攻击机制成立；迁移性待全长 run 判定

**不下「迁移性弱是科学结论」的判决** —— 那需要全长 run，5-round smoke 无权得出。

smoke 规模下观察到的分层模式（**仅作趋势记录，非结论**）：聚合层几乎无后门
（global/edge ≈ 0.007），same_edge(0.354) > diff_edge(0.092)。这与 §D 预测的
fedrep 壁垒方向一致，但 10 有效轮太短，后门尚无机会在 backbone 累积，无法区分
「迁移性真弱」与「训练不足」。**待全长 run 复核后才决定是否记为 negative result。**

## 与官方的建模差异（迁移性的可能来源，未做）

对拍 `reference/Bad-PFL`@`ad845a5` 发现两点 paper-faithful 的建模差异，均为「改建模」而非「调参」，作为后续可选实验：

- **P4 单一共享生成器**：官方 `fba.py:27` 用 closure 让**全部恶意端共享 1 个 generator + optimizer** 共同 co-train；本仓库每端独立 generator、eval 取 `mal[0]`。共享生成器天然跨模型泛化，是迁移性最可能的杠杆。**架构级改动**（需跨客户端共享可变对象），未做。
- 官方触发器绑定**目标类自然特征**（可迁移性来源），本仓库无此机制。

## 下一步：全长 run 才是迁移性的判据

smoke 已完成它的使命（接线 + 攻击机制）。要判 L2-二级迁移性，需一个**全长实验配置**，
使 `n_rounds × edge_rounds ≈ 300~500`（例如 edge_rounds=2 时 n_rounds≈150~250），
其余（10 client / cifar10 / hier_fedrep / badpfl / defense=none）沿用。这已不是
3 分钟 smoke，而是数小时级 GPU 作业，需单独配置文件（不要复用 smoke-base.yaml）。

P4（官方单一共享生成器）**本轮不做**（用户决定）。先用当前每端独立生成器的实现，

## 结论

1. **P4（共享生成器）确实提升迁移性**——benign 从平在 0.115 升到 ~0.16，diff_edge 近翻倍。
   证实「共享 vs 每端独立」是 Bad-PFL 迁移性的真实因素，我的 P4 移植方向正确。
2. **但 benign 在 round ~50 平台于 0.16-0.17**，远低于有效后门(>0.8)。机制预期非 bug：
   GM_ASR 全程贴地板 → 10% 恶意 + plain-mean 聚合下 backbone 后门强度处于低均衡；
   benign 干净私有 head 封顶表达。慢升→低位平台是攻击强度 vs 聚合稀释的均衡形状。
3. **官方实现已忠实移植完**（P4 是最大差异，已补；仅剩 P5 PGD 随机初始化，num_iter=1 下影响极小）。
   ~0.16 平台正收敛为「三层 hierarchical fedrep + 严格私有 head 设定下的忠实结果」。
