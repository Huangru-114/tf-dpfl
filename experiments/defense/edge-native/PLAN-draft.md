## 0. 一句话

后门**只经云聚合**跨 edge 传播（3-C），edge 没有检测优势（3-D），没有安全时段（3.3）→ 主线是**不依赖检测、一直开着、作用在上传前**的变换：
**edge 用自己的 500 张干净图在 body 上传云端前做加固（模块 A）**，与已证有效的 3-E edge 段组合。它**还没有任何证据说明有效**；第一步是零训练的离线判死探针。

## 1. 证据 → 设计（每条注明出处）

| 证据 | 对设计的约束 |
|---|---|
| 3-C：每次云聚合把受害 edge 灌高 0.13–0.27，周期内只洗掉 0.11–0.22（F-085 / F-086） | 干预点在**云聚合之前**；目标 = 让「灌入 < 洗掉」 |
| 3.3 `not_gated`（F-076） | 防御必须**一直开**，不能靠时机 |
| 3-D：edge 视角无增益；余弦 / 单更新 c_k 不可检测；`norm_s` 可零代价伪造（F-085） | **不依赖识别恶意端**；模块 B（软加权）降级 |
| 3-E：攻击者集中时 `blocks`（−0.52 / −0.73，fresh 代价 ≤ 0.02）；分散时无效；治不了 E0 的良性端（F-077 / F-069） | 已解决「集中 × 受害 edge」；**真正开放的是：分散布点、攻击者 edge 内的良性端** |
| G8 / G8F：攻击者走后后门自己褪去，margin 无平台（F-068 / F-071） | 后门对干净训练不稳 → 用干净数据清除**有可能**，问题是 500 张够不够快 |
| 攻击接近饱和（多处天花板） | 需要一个**不饱和的工作点**，否则防御效果只能靠 margin 看 |

**评审补出的范围约束**（务实视角）：阶段三的每一条线都要先回答「**能不能动分散布点、能不能动 E0 的良性端**」—— 只在「集中 × 受害 edge」上有效的东西与 3-E 重复。

## 2. 主线：模块 A（上传前加固）

- **作用对象**：上云的**可训练 body**（不碰 head、不碰私有 BN moving 统计量；k > 0 时可选只加固 cloud 段）。edge 没有可用的 head → 每次先在冻结 body 上拟合一个临时线性探针 head，用完丢弃。
- **目标函数**（离线筛选）：
  - O1 干净微调（对照：500 张干净图本身够不够）；
  - O2 TRADES（PGD ε，β ∈ {1, 6}）；
  - **O3 类感知的对抗遗忘**（I-BAU 式：对每个类拟合通用扰动，取最容易到达的类 k*，在 x + u_k* 上训正确标签；不需要知道 y_t）—— 主候选；
  - D1 NAD 式蒸馏（加固后的副本当老师）。客户端模型的集成蒸馏（FedDF）**不可行**：head 与统计量私有。
- **频率**：只在上传前（k = 0 时等价于原地加固，只能减少对别的 edge 的灌入）/ 每个 edge 轮（唯一能碰到 E0 良性端的办法，代价约 +64% 墙钟，外推）。
- **BN**：训练模式（干净批统计量）/ 冻结两种都筛；加固后私有统计量会陈旧 → 要另测「重新校准 BN 的 PM」，分清真实精度代价与部署假象（评审补充）。

## 4. 评审要求但三份方案都缺的（要在拍板时一起定）

1. **不饱和的工作点**：现在 R5 受害 edge 0.994–0.998、E0 0.97–1.0。建议加一个低强度威胁点（例如恶意端 2–5% 或 ρ 0.05–0.1；先 1 个探路包定强度），让防御效果能在 ASR 上看见 —— 否则「partial / no_effect」的边界没有意义。
2. **功效分析**：用 G1 / G1R5 / G6 已有数据估主量的 seed 间 SD，再定阈值与 seed 数（原文要求主结论 5 seed；F-085 已显示 R20 的标签在噪声里）。
3. **flat 对照**：同一防御在 flat FL 里也做一次 —— 否则效果不能归给「edge 原生」，而只是「干净数据微调」（G8F 已显示 flat 与 HFL 衰减相同）。
4. **改变布点 / 时机的自适应攻击者**：攻击者的最佳回应可能就是「分散 + 对加固自适应」，或只在广播后的 edge 轮投毒。
5. **评估用的固定攻击者**也必须是自适应版本，否则报告的 ASR 偏低。
6. **客户端 / 私有部分的选项**：白盒 ≈ 主列（私有 head 挡不住 ξ）；在客户端校准 head + 私有 BN 统计量也许能保护 E0 的良性端，且不需要信任 edge。
7. **隐私与部署论证**：cloud 只看到 edge 聚合；edge 每轮的额外算力；「每 edge 500 张可信干净图」是否现实 —— 测 100–200 张的敏感性。
8. **前置修复**：陷阱 #9（防御只看 body 索引）、陷阱 #2 第六处（FLAME 的全局 np.random）、陷阱 #3（FLAME 按文献）—— H5 之前必须修。

## 5. 降级 / 备选线（评审认为站得住、但不作主线）

- **结构性隔离**（阻尼 / 信任域、隔离）：只保护集中布点下的干净 edge，3-E 已覆盖；还会减少目前在清洗 E0 的稀释。保留两件：P0 里零成本的阻尼反事实；**oracle 隔离上界**（已知攻击者 edge、把它从云聚合里拿掉，看受害 edge 能多快恢复，约 7 GPU-h）—— 它给任何「减少灌入」的手段（包括模块 A 的上传前臂）一个上界。
- **抢救检测**（更好的 c_k：连续 margin、ε ≤ 2/255、步数 / n 的敏感性）：期望值低（单更新 k* 在随机水平；F-081 的 edge 级对比是在**不同的** body 上测的，已是弱的反面证据）。只作为 P0 的诊断量（加固后上传 body 的目标类 margin 是否回升），**不单独立项**；若要立项，硬上限 20 GPU-h、s42 选 / s43–44 确认、C2 ρ=0 混淆对照。
