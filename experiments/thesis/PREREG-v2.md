## 二、D0 结构核查（零训练，最先做）

✎ **原文写「在现有 B=1 run 的中间快照和末快照上核对」，但现有 B=1 run 都没有存快照**（全仓库存过快照的只有 SNAP 与 G8，都是 k = 0）。另外快照是**上传前**的边缘模型（本云轮最后一次边缘聚合之后、下一次广播之前），
所以「云聚合后四个边缘逐位相同」不能直接在快照上看。拆成两段：

**D0a（现在，CPU 上真跑小联邦；`tests/test_three_tier_personalization.py`）**，k ∈ {1, 2, 4}：一个云轮之后
- 上云段（共享块之前的各层）：广播后四个边缘逐位相同；
- 边缘段（最后 k 块）：同一边缘内所有客户端用的是同一份（fresh 个性化模型直接取边缘权重），边缘之间不同，且没被云广播覆盖；
- 分类头与 BN 运行统计量：每个客户端各不相同。

**D0b（D1 的 B=1 存快照重跑回传后；`fedavg/analysis/tier_structure.py`，回传 `experiments/defense/edge-native/analysis/d0_structure.json`）**，第 6 / 15 / 60 轮快照 × 3 个种子：
- 全局模型的上云段 = 四个边缘上云段的加权平均（最小二乘拟合 4 个权重，残差相对值 ≤ 1e-5，权重为正、和为 1）；
- 全局模型的边缘段在三个快照轮都不变（永远是初值），且与每个边缘的边缘段都不同；
- 四个边缘的边缘段两两不同；
- 客户端私有部分（分类头 + BN 统计量）两两不同，且不含边缘段的可训练权重。

切分 ✔（ResNet-10，`get_weights()` 的元素数，含 BN 统计量；`[设定6]` 实测 n_params = 4 909 002）：stem 1 984（0.04%）/ stage1 74 240（1.5%，**没有 shortcut**，10 个张量）/ stage2 230 912（4.7%）/ stage3 920 576（18.8%）/ **stage4 3 676 160（74.9%）** / 分类头 5 130（0.1%）。
B=1 上云 = stem + stage1–3（约 25%）。BN 统计量在主线下私有，所以「同一边缘内相同」只对卷积权重与 γ/β 成立。

结果写进 FINDINGS。任何一条不符 → 停下，6.1 需要重新审视。

## 三、D1 块数扫描（6.1 的代价对照）

**臂**（集中 [10,0,0,0]，主线划分，3 个种子；登记组 **TBS**）：

| 臂 | 上云的部分 | 上云参数比例 ✔ | 状态 |
|---|---|---|---|
| B=0 | 整个主干 | 100% | 已有（SNAP 集中） |
| B=1 | 最后一块之前的主干 | 25.1% | **存快照重跑**（`snapshot_rounds: "6/15/60"`，不设防），必须与 ERP / ERC main-t1 集中逐位相同（闸 ②） |
| B=2 | stem + 前两块 | 6.4% | 新跑 |
| B=4 | 只有输入层（stem） | 0.04% | 新跑；作为「几乎不上云」的隔离端点 |

前提代码：`fedavg/utils/tier_split.py` 的块数放宽到 0–4，连带 `fedavg/config_validate.py` 与 `tests/test_tier_split.py`；0 块路径逐字节不变（已有守卫）。

**判定量**：D = MTA(B=1) − MTA(B=4)，按种子配对，即 B=1 相对几乎完全隔离保住了多少精度。

| 分支 | 规则 | 论文写法 |
|---|---|---|
| `b1_meaningful` | 三个种子都 D ≥ 0.02 | B=1 是安全—精度前沿上一个有意义的点：保护接近隔离，同时保住了跨边缘共享的精度 |
| `isolation_free` | 三个种子都 \|D\| < 0.01 | 本设定下跨边缘共享几乎不带来精度收益，切断是免费的。6.1 收窄为「在本设定下与（几乎）完全隔离等价」，并写进有效性威胁（每个边缘约 9400 张训练图，可能已经够用） |
| `isolation_better` | 三个种子都 D ≤ −0.01 | 共享前几层反而有害。如实报告，6.1 同上收窄 |
| inconclusive | 其余 | 报数字，不报方向 |

阈值理由：0.02 与 3-E 的精度代价门槛（D-071）相同；G6 里同种子配对的精度差在种子之间只波动约 0.001–0.007。

措辞：B=4 仍有 stem 上云，论文写「几乎不上云」，不写「完全隔离」。

**只报告**（块数扫描图）：B ∈ {0,1,2,4} 的受害边缘 ASR、E0 良性端 ASR、MTA、陈旧个性化模型精度（`acc_rounds[].pm_acc_stale`，隔点记录，末 10 个评估点窗口）、上云参数比例。
另外核对单调性：受害边缘 ASR 应 B=4 ≤ B=2 ≤ B=1（不单调就标出来，不是判定）。
按类精度 ✔：**没有记录**（只有按类 ASR `cls_asr`）→ 不新增仪表，在有效性威胁里写明「个性化评估只测本地分布，可能低估共享的价值」。

## 四、D2 威胁边界 [9,1,0,0]

**设定**（登记组 **TBH**）：E0 = 9 个攻击者 + 16 个良性端；E1 = 1 个攻击者 + 24 个良性端；E2、E3 无攻击者。B ∈ {0, 1} × 3 种子 = 6 个 run，零代码。

**机制预测**（写在数据之前）：
- E2、E3 的最后一块只被良性端训练 → 受 B=1 保护，接近集中布点下的受害边缘；
- E1 的最后一块有攻击者参与训练 → 保护明显更弱；
- 不确定之处：E1 的攻击者只占 4%，被抽中的频率低（每边缘轮 2–3 个参与者，约 10% 的边缘轮抽到它）。一个攻击者够不够让 E1 失守，就是这个实验要测的。

**判定量**（按种子配对）：
- Δ_clean = ASR_{E2,E3}(B=0) − ASR_{E2,E3}(B=1)，E2、E3 取均值；
- Gap = ASR_{E1}(B=1) − ASR_{E2,E3}(B=1)，E1 只数良性端（`client_benign` 本来就只数良性端）。

| 判定 | 分支 | 规则 |
|---|---|---|
| 1 | `clean_protected` | 三个种子都 Δ_clean ≥ 0.30 |
| 1 | `clean_unprotected` | 三个种子都 Δ_clean ≤ 0.10 |
| 2 | `e1_breached` | 三个种子都 Gap ≥ 0.20 |
| 2 | `e1_also_protected` | 三个种子都 \|Gap\| < 0.10 |
| — | inconclusive | 其余 |

**解读**：
- `clean_protected` + `e1_breached`：符合「信任域」解释，6.1 的机制从「和数据一致」升为「事先预测、被检验」；
- `clean_protected` + `e1_also_protected`：一个攻击者不足以攻破，失效点在每边缘 1 个到 2–3 个攻击者之间，7.1 讨论；
- `clean_unprotected`：与预测相反，6.1 的有效条件改写为「攻击者只在一个边缘」，机制重新审视。

**只报告**：E0 良性端 ASR、各边缘 ASR、精度，与集中布点同种子的对照（SNAP / ERP / ERC）。

## 五、D3 离线探针（约 1–2 GPU 小时 + 一个离线脚本；后续会话实现）

复用 `fedavg/analysis/p0_snapshot.py`、`fedavg/hardening/core.py`、`fedavg/defense/edge_ref.py`、`fedavg/analysis/functional_score.py`；新配置另起清单，不改被测试锁定的 `p0_configs.yaml`。
三项都是**描述性**读数，作用是给论点升级证据强度。读法如下，跑之前定稿 ✎（原文的【待填】由 Claude Code 设计、用户 11-22 批准）：

**P-a 重训最后一块：后门有多少在最后一块**（支撑 6.1 的信任域解释）
- 对象：SNAP 集中 s42–44 第 15 / 60 轮快照的攻击者边缘 E0 模型（B=0）。⚠ 快照上 E0 良性端 ASR 在第 6 / 15 / 60 轮已是 0.82–1.00，所以 ASR 与 margin 都报。
- 做法：只训 stage4 的可训练权重（卷积 + γ/β），数据 = E0 自己的 500 张干净图，批 32、75 步（= P0 的 high 预算），SGD，lr = 当轮客户端主干 lr × 0.1（D-107 的稳定设置）。
  `EdgeHardener` 现在只能训全部主干 → 探针脚本里把 `body_vars` 换成 stage4 子集。
  训练后每个 E0 客户端在自己的训练分片上重估 BN 运行统计量（只前向、不训练）；「不重训」的基线做同样的重估，保证两边可比。
- 对照（同预算）：只训 stem–stage3；训全部主干。
- 触发器：主列语义（攻击者在 E0 上，ξ 在重训后的攻击者模型上重新求）；另报用重训前的 ξ（固定触发器）的读数。
- 读数：f = (ASR_前 − ASR_后) / (ASR_前 − 底线_E0)，底线_E0 = G0-C1（不投毒、同配置）E0 良性端末 10 点、同种子（0.097 / 0.063 / 0.073）。
- 闸：E0 良性端干净精度降幅 ≤ 0.05，否则 invalid（下降可能来自破坏而不是清除）。
- 规则：三个种子 f 都 ≥ 0.5 → 「后门主要在最后一块」；三个种子 f 都 < 0.25 → 「主要在前面的层，6.1 的机制解释要改写」；其余 inconclusive。

**P-b 在受害模型上直接求扰动：受害边缘低 ASR 是「后门没传过来」，还是「触发器迁移不过去」**（6.1）
- 对象：D1 的 B=1 存快照重跑第 60 轮，受害边缘 E1–E3 的良性端；SNAP 集中第 60 轮作参照。
- 做法：每个受害客户端在**自己的** fresh 个性化模型上求 ξ（白盒，单步 PGD、ε 同评估），δ 用评估攻击者的生成器；与主列（ξ 在攻击者模型上求）比。
- 规则：三个种子都 白盒 − 主列 ≥ 0.30 且白盒 ≥ 0.5 → 「触发器迁移不过去，后门功能在受害模型里存在」（6.1 改写为「隔离的是触发器的可迁移性」）；
  三个种子都 |白盒 − 主列| < 0.10 → 「后门没传过来」；其余 inconclusive。
- 另报：只有 ξ（δ = 0）与只有 δ（ξ = 0）的消融 —— 前者近似「普通对抗样本」的易感性底线。

**P-c 统计量偏移随后门强弱：参照过滤的反馈循环**（6.3）
- 单位：「run × 快照轮 × 边缘」的边缘模型 —— SNAP 集中 + 分散（6 个 run）与 D1 的 B=1（3 个 run），第 6 / 15 / 60 轮，每 run 4 台边缘，共 108 个。
- 后门强度 S：该边缘良性端触发样本 margin 中位数在该轮的记录值（`per_edge_detail_rounds`）。
- 统计量偏移 Δ：该边缘 500 张干净图，加触发器（主列：攻击者模型上的 ξ + 生成器 δ）前后，在该边缘模型上一整批训练模式前向，各 BN 层输入逐通道矩的高斯 KL，取各层均值
  （复用 `defense/edge_ref._moments` + `edge_ref_spec.gauss_kl`）。
- 规则：合并 Spearman ≥ 0.5、三个种子内各自 > 0、置换检验 p < 0.01 → 反馈循环从「弱」升为「中」；合并 Spearman ≤ 0.2 → 不支持（6.3 的解释维持「未直接验证」并写明）；其余 inconclusive。
- 备注：F-129 的 0.57 是单个 run 内逐云轮的 Pearson（`harness/thesis_figures.py` 能复现）；t1 的 0.71 没有脚本 → 论文只引用能复现的数。

## 六、D4 逐坐标中位数基线

**设计问题** ✔：每个边缘轮每个边缘只有 2 或 3 个上传（交替）。2 个数的中位数就是（不加权的）平均，3 个数的中位数只是取中间那个。所以边缘层中位数的失败本身就是「边缘内多数原则行不通」的证据（INTEGRATION-PLAN 的读法），
但单独拿它当鲁棒聚合的代表，会被质疑是稻草人。云层中位数作用在 4 个边缘模型上，集中布点时只有 1 个被污染，又正好位于灌入点，是对 B=1 最公平的对手。

| 臂 | 边缘聚合 | 云聚合 | 配置 | 角色 |
|---|---|---|---|---|
| Me | 参与者模型的逐坐标中位数 | 平均 | `defense: {name: median, layers: [edge]}` | 必做 |
| Mc | 平均 | 4 个边缘模型的逐坐标中位数 | `defense: {name: median, layers: [cloud]}` | 主对照（D-135 ①） |

✎ 查实：Mc **不需要改训练代码** —— `layers: [cloud]` 通过 `config_validate`，边缘层回落为样本加权平均；`CloudServer.aggregate_edges` 经 `robust_mean` 调中位数。
要补的只是 harness 的自描述：`run` 块现在不记录 `defense.layers` → `collect_metrics` 解析已有的 `[Defense] enabled: median @ cloud` 行写进 `run.defense_layers`。

两臂都在 B=0 上，× 集中 / 分散 × 3 种子 = 12 个 run（登记组 **MED**）。不用 Multi-Krum：它会把私有分类头算进距离（陷阱 #9）。

**实现约定** ✔：中位数作用在现在做平均的同一组参数上（`MedianDefense` 对上传的全部张量逐坐标取中位数，FedRep 的边缘服务器之后只取主干索引 —— 主干可训练权重 + BN 的 γ/β + BN 统计量；私有分类头的结果被丢弃；逐坐标运算，分类头不影响主干坐标）；
偶数个元素取中间两个的平均（`np.median`）；单元测试覆盖手造张量（n = 2 / 3 / 4）。不加权（各端等大，对边缘层无影响；云层 4 个边缘等权）。

**判定**：与 3-E（D-071）同一规则：ΔASR = ASR(B=0) − ASR(M) 三个种子都 > 0，且 MTA 下降均值 ≤ 0.02 **且**逐种子都 ≤ 0.02（与 `g6_verdict` 相同，两种读法都报告）→ `blocks`。
✎ 判定量：集中布点用受害边缘 ASR V；**分散布点没有受害边缘 → 用全部良性端池化 ASR P**（同 N-014 / CCS 线）。
因为 D-071 只要求方向，报告时必须同时给出效应量，以及与 B=1 的对照（B=1 = ERP / ERC main-t1 同布点同种子）：
- ASR(M) − ASR(B=1) 三个种子都 ≥ 0.10 → `weaker_than_b1`；
- 三个种子都 ≤ −0.10 → `stronger_than_b1`；
- 三个种子都 \|·\| < 0.10 → `comparable_to_b1`；
- 其余 inconclusive。

**事先写下的预期**（不是规则，用来防止事后合理化）：
- Mc 在集中布点下能压低受害边缘，但会丢掉良性的边缘特有信息，精度代价可能超过 0.02；分散布点下无效；
- Me 在集中布点下（E0 约 40% 恶意）无效，分散布点下可能有小幅作用。

**只报告**：E0 良性端 ASR、陈旧个性化模型精度、云聚合后点的 Δ_jump（给 M4）。

## 七、A 攻击基线（后续会话）

**两个问题，对应论文两处**：
- **A-Q1（刻画，进第 5 章一小节）**：比 Bad-PFL 弱的攻击，在三层 + FedRep 下能不能植入、能不能跨边缘传播？它回答「为什么必须研究 Bad-PFL」，在分层设定下复核 Qin 等 KDD 2023 与 ACISP 2026 的结论。
- **A-Q2（泛化，进 6.5）**：对能传播的攻击，6.1（B=1）和 6.2（上传前加固）是否仍然有效？

### 阶段 A1：探路与分流

- 6 种攻击（BadNets、Blended、DBA、Neurotoxin、CerP、IBA）× 种子 42 × 不设防 × 集中 × 主线划分 × 300 有效轮。
- 每种攻击先出语义对照表，再写接线代码。数据要走 `per_epoch` 取数路径，否则会被 `config_validate`（`fedavg/config_validate.py:613-618`）拒绝。
  ✔ 现状：P2 模板要求 `per_epoch`，而只有 Bad-PFL 接了；静态三种要写一个 `on_batch` 每批投毒的 mixin（照 Bad-PFL 的 `poison_mask`），CerP 的触发器训练要改读 `epoch_batches`，
  IBA 仓库主线没有实现（分支 `origin/claude/iba-attack-integration-vt3jjm` 有一版 9 月的草稿，早于 P2 与攻击时间窗，只能作起点）。
  ✔ 静态攻击目前没有云聚合后评估点（`post_agg_eval` 只对 Bad-PFL 开放）→ 接线时一并处理，否则进不了 M4 的灌入—洗掉表。
- 投毒率与恶意端数默认同 Bad-PFL（ρ = 0.2，10 个）；攻击设计要求不同的，在语义表里写明理由。

**分流规则**（看末 10 点原始 ASR；这是路由决定，不是论文结论）：

| 分支 | 规则 | 去向 |
|---|---|---|
| `propagates` | 受害边缘良性端 ASR ≥ 0.30 | 进 A2 正式实验 |
| `local_only` | E0 良性端 ≥ 0.30，受害边缘 < 0.30 | 补种子 43、44（不设防），作 A-Q1 的证据 |
| `no_implant` | E0 良性端 < 0.30 | 补种子 43、44（不设防），作 A-Q1 的证据 |

A-Q1 的论文结论：三个种子都落在同一分支，才写成结论；否则写成单种子观察。静态触发器没有 Bad-PFL 式的 ρ=0 底线，原始 ASR 旁边附上干净样本被判成目标类的比例作参照（报告里约 0.011–0.020）。

### 阶段 A2：正式实验（只对 `propagates` 的攻击）

- {不设防（复用 A1 + 补 2 个种子）, B=1, 上传前加固} × 集中 × 3 种子；
- 判定同 D-071（`blocks`），并报告与 Bad-PFL 下效应量的对照；
- **分散布点不做**（D-135 ⑤；B=1 在分散布点下的失效已由机制解释、由 Bad-PFL 数据验证）。

### 优先级与时间盒

| 顺序 | 攻击 | 理由 |
|---|---|---|
| 1 | BadNets、Blended、DBA | 共用静态投毒路径，一个接线会话搞定三个 |
| 2 | IBA | 仓库主线没有实现，要照官方代码新写；但它和 Bad-PFL 最接近（生成器式、L∞ 噪声触发器），最可能 `propagates`，A-Q2 主要靠它 |
| 2.5 | 自适应攻击者（最小版） | 直接检验 6.1，答辩最可能被问；优先级高于第 3 档（D-135 ④） |
| 3 | Neurotoxin、CerP | 各有已知的代码风险：Neurotoxin 掩码方向未证实（陷阱 #4）；CerP 的触发器训练仍读旧数据管线。设计目标分别是持久性和躲避检测，不是 6.1 / 6.2 针对的问题 |

**时间盒：2026-12-06**（D-135 ③）。到期还没接通的攻击写进局限，不再追。

**自适应攻击者（最小版，D-135 ④）**：知道最后一块不上云的 Bad-PFL 攻击者 —— 投毒训练时 stage4 的梯度置零，只往上云的层植入（生成器照常）。集中 × B=1 × 3 种子 = 3 个 run（短代码会话：攻击 mixin 里按 `tier_split` 的边缘段索引屏蔽梯度）。
- 闸：E0 良性端 ASR ≥ 0.5（否则 `invalid_no_implant`：屏蔽最后一块后攻击本身植不进去，不能读成 B=1 守住了）。
- 判定量：ΔV = V(自适应, B=1) − V(Bad-PFL, B=1)，按种子配对（后者 = ERP / ERC main-t1 集中或 D1 的 B=1 重跑）。
- 规则：三个种子都 ΔV ≥ 0.30 → `b1_breached`（6.1 写明「对知道边界的攻击者无效」）；三个种子都 ΔV < 0.10 → `b1_holds`；其余 inconclusive。
- 只报告：B0、MTA、灌入量（云聚合后点 − 上一云轮末）。
