## 一、一句话叙事

**在「云端 – 边缘服务器 – 客户端」三层个性化联邦学习里，优化型后门是在云聚合那一刻跨边缘扩散的；边缘服务器看不出谁在投毒，但它可以决定哪些东西跨过云端边界 —— 防御的杠杆在机构之间的边界上，而不在机构内部。**

三个研究问题（沿用阶段二的提法，阶段三是第三问的展开）：
1. 后门在三层结构里怎样植入、扩散、褪去？
2. 边缘服务器能看到什么、什么时候能干预？
3. 边缘服务器能做哪些干预，各自为什么有效或无效？

论文标题方向（示意）：「边界上的防御：分层个性化联邦学习中优化型后门的传播机制与边缘侧防御」。

## 二、贯穿全文的分析框架：每个云周期的「灌入 − 洗掉」

阶段二测出：每次云聚合把后门「灌」进干净边缘（受害边缘跳升），两次云聚合之间边缘内训练「洗掉」一部分；
每个周期的净增量 = 灌入 − 洗掉，净增量 > 0 就一路走向饱和；攻击者一走，同一个洗掉过程表现为缓慢衰减。
这把尺子把所有防御放进同一个框架：防御要么减少灌入、要么加快洗掉、要么减少攻击者的贡献。

阶段三的全部实验都开着云聚合后评估，所以**不需要新训练**就能把各臂放进同一张表（`harness/defense_balance.py`，**描述性分析，不是预注册判定**）。
集中布点、受害边缘、前半程（第 2–30 云轮）三个种子：

| 臂 | 灌入（攻击成功率口径） | 灌入（margin 口径，logit） | 每周期净增量（攻击成功率） | 受害边缘终值 |
|---|---|---|---|---|
| 不设防 | 0.220 / 0.222 / 0.148 | 2.00 / 2.00 / 1.75 | 0.026 / 0.032 / 0.033 | 0.996 |
| 三层个性化（最后一块不上云） | 0.035 / 0.072 / 0.071 | 0.94 / 1.20 / 1.01 | 0.001 / 0.008 / 0.010 | 0.281 |
| 上传前加固 | 0.174 / 0.223 / 0.142 | 1.37 / 1.44 / 1.07 | 0.012 / 0.022 / 0.030 | 0.587 |
| 参照过滤 | 0.059 / 0.224 / 0.073 | 1.25 / 2.39 / 1.46 | 0.003 / 0.020 / 0.005 | 0.536 |
| 参照过滤 + 三层个性化 | 0.007 / 0.091 / 0.008 | 0.41 / 1.35 / 0.52 | −0.001 / 0.013 / 0.002 | 0.184 |

读法（两个口径要一起报）：
- **攻击成功率口径**：三层个性化把灌入砍到 1/3–1/6；上传前加固的灌入几乎不变（F-124 的原读法）；参照过滤前半程能砍、后半程灌入回升到 0.15–0.20（与反馈循环一致，F-129）。
- **margin 口径**（触发样本上「目标类对数概率 − 其余类最大对数概率」的中位数，饱和时更有动态范围）：三层个性化把灌入砍掉约一半（降 0.74–1.06 logit），
  上传前加固也砍掉约三分之一（降 0.56–0.68 logit）—— **两者差距比攻击成功率口径显示的小**。攻击成功率是带阈值的量，会放大差别。
- → 论文里机制部分以哪个口径为主，写之前要定（见 `OUTLINE.md` 待定事项）；正式出图前把分析规则写明、再算全部布点与种子。

**防御侧（Bad-PFL 下）必须补（约 22 GPU 小时 + 两个短代码会话）**

3. 零训练离线探针（≈ 1–2 GPU 小时 + 一个离线脚本）：重训最后一块（后门有多少在最后一块）、在受害模型上直接求扰动（后门没过来 vs 触发器迁移不过去）、触发器引起的统计量偏移随后门强弱的变化（反馈循环的直接验证）。

**攻击侧（2026-11-19 用户决定：无论产出目标如何都要补并做实验，只是规模不同）**
4. **先做完 Bad-PFL，再做一组比 Bad-PFL 弱的基线攻击**，之后再定规模（包括「知道最后一块不上云的攻击者」做多大）。
   代码事实（2026-11-19 核对）：正式口径下数据按 epoch 重洗（`data.batch_pipeline: per_epoch`），而**只有 Bad-PFL 接了这条取数路径**；
   静态投毒（BadNets / Blended / DBA，`malicious_strategy: vanilla`）、Neurotoxin、CerP 都会被 `fedavg/config_validate.py` 的对应检查拒绝启动
   （否则恶意端会静默变成良性端）。所以较弱的基线攻击要先写接线代码；Neurotoxin 另有掩码方向未证实的问题（CLAUDE.md 陷阱 #4），CerP 的触发器训练仍读旧数据管线。
   **已定（2026-11-20）**：BadNets、Blended、DBA、Neurotoxin、CerP、IBA（IBA 仓库里没有实现，要照官方代码新写）；先各跑 1 个探路实验，植进去的再进正式实验（`OUTLINE.md` 第七节第 2 条）。

**防御侧建议补**
5. 边缘上的逐坐标中位数基线：集中 / 分散 × 3 个种子 ≈ 9 GPU 小时（零代码；多 Krum 会把私有分类头算进距离，陷阱 #9，不选）。每台边缘每轮只有 2–3 个上传，这一点本身就是「边缘内多数原则行不通」的证据。

**降级为局限或附录**

- 目标类分布：攻击饱和、判不出 → 附录。结构延迟：只有 1 个种子 → 附录或不提。私有分类头吸收：没做 → 背景一句话。

| 创新点 | 证据 | 强度 |

| 首次在机构式三层个性化联邦学习里系统刻画优化型后门的植入、扩散与衰减 | 机制章全部；文献核查未见同类 | 强（需补被引用查询） |

| 边缘视角没有检测优势 | 可观测性预注册判定 | 强 |
| 把私有边界从客户端分类头上移到边缘级的最后一块，就恢复了对 Bad-PFL 的跨边缘隔离 | 两种划分 × 3 个种子 + 灌入下降；补充 1–3 | 效果强；代价与边界待补 |
| 依赖「模型已学会后门」的检测信号放进在线过滤会形成反馈循环，离线可分性高估在线效果 | 过滤实验 + 相关性读数；补充 3 | 中（补充 3 后升级） |

措辞底线：结构本身有先例（边缘级个性化只为精度）、统计量检测有先例（BNGuard、CCS）、边缘持干净数据作信任锚有先例（FoggyTrust）、
不分层个性化里部分共享抗后门有先例（Qin 等 KDD 2023），都在相关工作里正面写出；创新落在「组合 + 机制 + 边界」。
